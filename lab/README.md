# The deliberation lab (experiment)

**Status:** built 2026-10-03 and proven end to end **on a fake model only**. Nothing here has met a real
LLM yet. · **Design:** [deliberation-lab.md](../docs/research/dspy/deliberation-lab.md),
[DL-264](../docs/design-log.md), and [the DSPy 3.4 notes](../docs/research/dspy/practitioner-notes-3.4.md).

**What it answers.** Given a prompt variant and a set of cases, do the three deliberators **understand**
the evidence, **use** it, and decide on **market evidence**? It does not just deliver a verdict.

**Ground rules** (operator, 2026-10-03):

- This is an experiment, deliberately outside the repo's CI gates.
- **It must not break anything that exists.** It changes no production file, no root config, and not
  `uv.lock`. It writes nothing to the graph, the bus, the fleet or the broker. The repo's
  `ruff check .` and `ruff format --check .` still pass, using `lab/pyproject.toml`.
- It runs in the repo's own environment, with DSPy from the existing `optimizer` extra (3.4.0,
  already locked).
- **ALL quant numbers are presented to the deliberators and interpreted by them** (house rule H12,
  form law DEC-FORM-07). Each reading copies the value, names the scale, states the meaning here, and
  gives a direction and a weight.
- **The two scope decisions** (DL-264 amendment 8):
  - **Who reads what.** The judge reads **every** number. The pro and con read every number of
    **evidence** and may skip **bookkeeping**: thresholds, counts, prices and account plumbing, as
    tagged in the dictionary. Any new number defaults to evidence, so it is read by everyone until
    someone decides otherwise.
  - **Unproven numbers.** Model outputs whose skill isn't yet shown live, starting with the **barrier
    forecast**, are **presented and read, but may never carry a decision alone** (house rule H13,
    form law DEC-FORM-08). When the skill is proven, the tag is removed and nothing else changes.

## What is in it

| Piece | File | What it does |
| --- | --- | --- |
| Cases | `deliberation/scenarios.py`, `cases.py` → `cases/synthetic/*.json` | Eight named market situations. Each is pushed through the **fleet's own** scanner, analyst and PM (with the pack's overrides), then the **production renderer** `build_veto_context`. The packet is exactly what the deliberators would see. Each case holds a **baseline book of four unrelated holdings at about 25 % deployment**, like the live fleet, so the sector and correlation gates evaluate on real numbers |
| Supplement | `cases.py:_supplement` | The numbers the fleet's code computes **but production never shows**. MACD line and signal, stochastic %D and the OBV signal line decide sub-scores and are hidden today. Also the SMA-50/200 and EMA levels, the Bollinger bands, account cash, equity and buying power, holdings, the VIX status and date, the decision-time ATR, and the **barrier forecast**, computed by the forecaster's own GARCH fit and path simulation over a 760-bar history |
| Book I, the dictionary | `book/entries.py`, `dictionary.py` → `book/generated/dictionary.md` | **160 entries, every number in every packet**, each tagged evidence or bookkeeping, proven or unproven (`book/coverage.py` proves ALL DEFINED). The bands are generated by probing the scorers, so they cannot drift from the code. Keys that embed a ticker or period match by pattern. Keys rendered in two units in one packet are declared |
| Book III, house rules | `book/house_rules.py` | 13 rules with citations, and falsifier patterns for false statements |
| Typed outputs | `outputs.py` | `Brief` (readings of every number, gaps, case) and `Ruling` (own readings of every number, decisive keys, market conditions, accepted, rejected, ruling, rationale) |
| Decision code, Tier A | `laws.py` | DEC-FORM-01..08, checked by code. 07 is completeness, by tier: the feedback lists every number not yet read. 08 says an unproven number cannot carry a ruling alone. All feedback quotes the dictionary |
| The trio | `program.py` | DSPy signatures. The book goes in the **system message**, through a custom adapter. Topologies **T0** (sequential debate, N rounds) and **T2** (independent briefs in parallel, then a deciding judge). Instruction arms `production` and `lab` |
| Engines | `engines.py` | A deterministic fake ($0), or real `dspy.LM` (Anthropic / OpenAI). **No temperature is ever sent**, because Opus 5.5 rejects it |
| Runner | `run.py` | Each seat gets **one form-law retry** (our own loop, not `dspy.Refine`). Every real run is costed and refused without `--max-usd`. The report covers rulings, **coverage per seat**, violations, **whether the seats agree on what each number means**, and per-key reads and misreads |
| Compare | `compare.py` | Several runs side by side |
| Iteration 1, step 1 | `prompt_audit.py` | Is the prompt valid, and does it carry ALL the quant data? It renders the exact messages and checks values, packet, definitions, rules, schema and ceiling. $0 |
| Iteration 1, step 2 | `explain_models.py`, `explain_grade.py`, `explain_run.py`, `explain_fake.py` | Do the seats **understand** the data? They explain, without deciding: each number as an indicator, then the numbers in combination. Graded by code against the analyst's own scorers, first attempt only |

## Run it

From the repo root:

```bash
# 1. rebuild the cases and the dictionary (deterministic, $0)
PYTHONPATH=. uv run --frozen --extra optimizer python -m lab.deliberation.cases
PYTHONPATH=. uv run --frozen --extra optimizer python -m lab.deliberation.book.dictionary
PYTHONPATH=. uv run --frozen --extra optimizer python -m lab.deliberation.book.coverage

# 2. prove the machinery on the fake model ($0)
PYTHONPATH=. uv run --frozen --extra optimizer python -m lab.deliberation.run \
    --variant lab/deliberation/variants/lab_t2_book_complete.json --engine fake --out /tmp/lab/fake

# 3. iteration 1: prompt validity ($0), then the explain test (fakes $0: good must pass, flawed and hedging fail)
PYTHONPATH=. uv run --frozen --extra optimizer python -m lab.deliberation.prompt_audit \
    --variant lab/deliberation/variants/lab_t2_book_complete.json --out /tmp/lab/prompts
PYTHONPATH=. uv run --frozen --extra optimizer python -m lab.deliberation.explain_run \
    --variant lab/deliberation/variants/lab_t2_book_complete.json --engine fake-flawed --out /tmp/lab/explain-fake
PYTHONPATH=. uv run --frozen --extra optimizer python -m lab.deliberation.explain_run \
    --variant lab/deliberation/variants/lab_t2_book_complete.json --engine real --max-usd 3 \
    --cases falling_knife,value_trap --out /tmp/lab/explain-first

# 4. real models (needs ANTHROPIC_API_KEY in the shell; refuses without a cap). Cheapest first look:
PYTHONPATH=. uv run --frozen --extra optimizer python -m lab.deliberation.run \
    --variant lab/deliberation/variants/lab_t2_book_complete.json --engine real --max-usd 3 \
    --cases falling_knife,value_trap --out /tmp/lab/first
PYTHONPATH=. uv run --frozen --extra optimizer python -m lab.deliberation.compare /tmp/lab/<run> /tmp/lab/<run> ...
```

## The variants (`deliberation/variants/`)

Every variant runs with `coverage: decision_rule` (the judge reads every number, the debaters every
number of evidence) and a 32,000-token output ceiling per call. Estimates are printed before each run;
these are the current ones *[estimate: about 60 output tokens per reading, plus case text and a
thinking allowance]*:

| Variant | Question it answers | 8 cases, expected (worst case) |
| --- | --- | --- |
| `today_prod_t0_opus5` | How does today's set-up read the evidence? (production prompts, no book, 2-round debate, Opus 5) | $10.98 ($78) |
| `prod_t0_nobook` | What does the model change alone do (Opus 5.5)? | printed |
| `prod_t0_book` | What does the **book alone** add? | printed |
| `lab_t0_book` | What do lab instructions add, on today's debate shape? | $9.89 ($65) |
| `lab_t2_book` | The operator's design: independent briefs and a deciding judge | printed |
| `lab_t2_book_complete` | The same, with **every computed number presented** (about 30 more per case, including the barrier forecast) | $6.86 ($39) |
| `lab_t2_book_complete_strict` | The same, but every seat reads every number: what the relaxation saves | $7.91 ($39) |

For two cases on `lab_t2_book_complete`: $1.71 ($9.71).

🪤 **The `production` instruction arm is production's role text inside the lab's typed output
contract**, not a byte-for-byte replay. Production's judge prompt asks for a one-line JSON answer, and
here it gets the typed `Ruling`, with every number to read, instead.

## What the fake run proves, and what it does not

**[measured 2026-10-03, fake engine]**

| Variant | Numbers read (first attempt → after retry) | Violations | Calls |
| --- | --- | --- | --- |
| `lab_t2_book` | 2 % → 100 % (133–138 numbers per seat) | 91 → 0 | 48 |
| `lab_t2_book_complete` | 2 % → 100 % (158–163 numbers per seat) | 91 → 0 | 48 |
| `prod_t0_book` | 2 % → 100 % | 141 → 0 | 80 |

DEC-FORM-07 failed all 24 first attempts on `lab_t2_book_complete`, by design of the fake, and the retry
listed every unread number. **It proves** that cases, book, supplement, adapter, both topologies, the
checker, completeness, the retry, the cost ledger, the spend refusal and the report all work together.
**It proves nothing about the real expert.** The fake's rulings and its 100 % agreement are scripted.
Whether Opus 5.5 can write about 160 correct interpretations per seat, within the ceiling and the
budget, is the first thing the real run will show.

## Already learned from the synthetic cases (real code, no LLM)

- **Upstream gates already stop the crudest cases.** A plain downtrend and a falling-price value trap
  are dropped by the scanner's minimum relative strength. A strongly negative news day drives the
  sentiment pillar to 0 and the analyst's confidence below its 0.60 floor. The scenarios were tuned so
  that each one reaches the referee.
- **The falling knife is bought.** RSI 24, 20 % below the 200-day average, relative strength −15 points:
  the composite is 0.532, which gives confidence 0.619, which clears the 0.60 floor. The contrarian
  sub-scores (RSI 80, stochastic 80, Williams 75, Bollinger 75) lift it.
- **Its reward/risk is 0.57 and the gate PASSES.** The target is 2.66 % against a 4.64 % stop, because
  the gate is disclosure-only at threshold 0.
- **Numbers that decide sub-scores are hidden.** The MACD line, stochastic %D and the OBV signal decide
  three sub-scores, and the production packet shows none of them. The falling knife's MACD line is
  −7.61, below its signal at −7.26, which is why its MACD sub-score is 25.
- **One packet carries the same quantity in two units, and two quantities under one name.** `stop_pct`
  appears as 4.64 % in one line and 0.0464 in another. `relative_strength` is −15 percentage points
  from the analyst and 0.579 as a fraction from the scanner. And `pe=60` sits beside
  `peBasicExclExtraTTM=19`.
- **At low deployment the correlation gate does not look.** With the book nearly all cash, the gates
  printed `NOT-EVALUATED`. At about 25 % deployment they evaluate: the twin's correlation of 0.695 with
  a holding counts at weight 0.489, giving a cluster ratio of 0.117 against a cap of 0.25, so it PASSES.

- **An unproven model can be confidently wrong on exactly the cases that matter.** For the falling knife,
  the forecaster's GARCH, fitted mostly on the long run-up before the break, gives an **81 %** chance
  of reaching the target first. That is why H13 lets the forecast inform a ruling but never carry one.
  *[Caveat: the synthetic series are smooth and periodic, so their GARCH numbers test how the
  deliberators handle an unproven input, not how good the forecaster is.]*

## Iteration 1: is the prompt valid, and is the data understood?

**[measured 2026-10-03; design and pass bar in DL-264 amendment 9]**

- **The prompt is valid, on 8 cases × 3 seats.** Every number the analyst computed reaches the packet
  with its value; the packet is intact; every number's definition is in the system message; all rules
  and the schema are present. The judge reads 164–169 numbers, the debaters 110–112. Production
  withholds 31–33 numbers per case.
- **What the explain test asks of each seat**, without deciding:
  - (a) for each number: its indicator family, unit, meaning here, direction for this buy, and the
    0–100 sub-score a raw indicator maps to;
  - (b) the six aggregates reproduced from their parts, a verdict per pillar, the interactions
    between numbers, and the situation.
- **The pass bar, pre-registered:**
  - coverage 100 %;
  - value 98 %, scale 95 %, family 90 %, direction 90 %, sub-score 90 %;
  - **critical 100 %**: no contrarian oscillator read the wrong way round, and no sub-score read as
    a ratio;
  - derivations ≥ 5/6, pillars ≥ 5/6, interactions ≥ 70 %;
  - first attempt only.
- **The grader tells the fakes apart:**

  | Fake | Behaviour | Passes |
  | --- | --- | --- |
  | `good` | answers from the keys | 24/24 |
  | `flawed` | reads like an untrained model | 0/24 |
  | `hedging` | right, but calls every direction neutral | 0/24, failing only direction and critical |

  An averaged score alone would have let the flawed reader's RSI misreading through on the extended
  leader (92 % direction); the critical check catches it.
- **Not yet run on a real model.** Two cases ≈ $2.27 ($4.07 worst case); eight ≈ $9.12 ($16.29).
- **For the operator to approve:** the expected interactions per scenario
  (`explain_grade.EXPECTED_INTERACTIONS`), beside each scenario's `expert_view`.
